**Memory** is a long-term knowledge store for your workspace. It reads chat conversations and files you choose, pulls out the facts that matter (decisions, preferences, details), and lets you search them later, even months afterwards.

A chat remembers only its own thread. Memory remembers what matters across conversations.

This page is for developers who want to add and search knowledge through the API. You need a [personal access token](/api/authentication) with the `memory:read` scope to search, and `memory:write` to add knowledge.

## What memory stores

| Source | How it gets in |
|--------|----------------|
| Chat conversations | You call the index-conversation endpoint |
| Work files | You call the index-file endpoint |

Everything is kept separate per workspace and project. No one can search another workspace's memory.

Memory is not the same as workflow data. Step results in `{{steps.*}}` only exist during one run. Memory stays after the run ends.

## Add knowledge

Adding knowledge is called **indexing**. It runs in the background: you start a job, then check it.

### Index a conversation

```
POST /v1/memory/index-conversation
```

```json
{
  "conversation_id": "conversation-id",
  "project_id": "your-project-id"
}
```

Both fields are required. The reply is `202 Accepted` with a job. Check it with `GET /v1/memory/extract/{jobId}`.

### Index a file

```
POST /v1/memory/index-file
```

```json
{
  "file_id": "work-file-id",
  "project_id": "your-project-id"
}
```

### Index many things at once

For a large backfill, start a batch with `POST /v1/memory/extract/batch` and check it with `GET /v1/memory/extract/batch/{batchId}`. Batches run in the background and can take longer than single jobs.

## Search memory

```
POST /v1/memory/search
```

```json
{
  "query": "What did we decide about Q2 pricing?",
  "limit": 10,
  "project_id": "your-project-id"
}
```

**What you should see:** the stored facts that best match the question. An empty memory returns no results. Facts only appear after their indexing job has finished.

To read one stored episode in full, call `GET /v1/memory/episodes/{episodeId}`. Add `?detail=false` to leave out the details.

## Memory for agents

When memory is enabled for your workspace, an agent can search memory before each reply, so it can use what it learned in earlier conversations. Workflows get memory through **agent** steps. **LLM** steps do not search memory.

Chats can also be added to memory automatically as they happen. This is not switched on by default. Ask [support](mailto:support@agentruntime.io) if you want it for your workspace.

## Credits

Indexing conversations and files uses credits. **Settings → Usage & History** in the Console shows your usage. See [Billing and credits](/platform/billing-and-credits).

## Limits

- No Memory screen in the Console yet. You work with memory through the API
- Indexing is not instant. Check the job before you expect to find the facts
- Search quality depends on what you have indexed

## Common problems

| Problem | What to do |
|---------|------------|
| `503` and `memory kernel not configured` | Memory is not available in your workspace. Ask [support](mailto:support@agentruntime.io) |
| `400` on index-conversation | `conversation_id` and `project_id` are both required |
| `403` | The token needs `memory:write` to index and `memory:read` to search |
| Search returns nothing | Check that the indexing job finished, and that you indexed the right project |
