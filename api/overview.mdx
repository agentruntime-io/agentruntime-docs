The AgentRuntime **REST API** lets your own code do what you do in the Console: create and run workflows, approve human tasks, manage connections, and read usage. This page is for developers who are new to the API. It explains the basics and points you to the right next page.

**Base URL:** `https://api.agentruntime.io`

## What you need

- An AgentRuntime workspace, and a role that allows what you want to do ([roles](/platform/roles-permissions))
- A personal access token (PAT). See [API authentication](/api/authentication) to create one in a few clicks
- A tool that can send HTTPS requests, such as `curl`

## Try it in one minute

Create a token with the `workflow:read` scope, then run:

```bash
curl "https://api.agentruntime.io/v1/workflows" \
  -H "Authorization: Bearer pat_YOUR_TOKEN"
```

**What you should see:** a JSON list of the workflows your token can see. If you get `401`, check the token. If you get `403`, add the missing scope.

To start a run:

```bash
curl -X POST "https://api.agentruntime.io/v1/workflows/WORKFLOW_ID/command" \
  -H "Authorization: Bearer pat_YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"command": "start", "params": {"trigger_payload": {"customer_id": "123"}}}'
```

The token needs `workflow:run` (and `mcp:execute` if the workflow has MCP steps). The reply contains a `run_id` you can use to follow the run. More samples are in [API examples](/api/examples).

## What the API covers

| Area | Paths | Use it to… |
|------|-------|------------|
| Workflows | `/v1/workflows` | Create, edit, publish, validate, and run workflows |
| Runs | `/v1/runs`, `/v1/workflows/{id}/runs/...` | Follow runs and read their events and results |
| Human tasks | `/v1/tasks/pending`, `/v1/workflows/.../tasks/...` | List and complete approvals |
| Webhooks | `/v1/inbound-webhooks` | Let other systems start runs |
| Integrations | `/v1/connections`, `/v1/mcp/*` | Manage connections, MCP servers, and instances |
| AI | `/v1/autopilot/*`, `/v1/memory/*` | Autopilot and memory |
| Account | `/v1/billing/*`, `/v1/analytics/*`, `/v1/pats` | Usage, billing, analytics, and API keys |

Every endpoint, with the role it needs, is in the [API reference](/api/reference).

## How requests are scoped

A token belongs to one workspace, and optionally to one project. Requests made with it are automatically limited to that workspace and project, so you do not send any workspace header. Console sessions in a browser use the workspace and project you have selected.

## Working from an AI assistant

If you would rather ask an assistant than write HTTP requests, connect it to [Platform MCP](/api/platform-mcp). It offers the same operations as tools.

## Errors and limits

The API uses standard HTTP status codes. `401` and `403` mean sign-in or permission problems, `422` means the request was understood but is not valid (for example a workflow graph with an error), and `429` means you are sending too fast. Wait for the time in the `Retry-After` header, then retry. Retry `5xx` responses with exponential backoff. The full list is in the [API reference](/api/reference#responses-and-errors).
