These guides walk you through **complete workflows** you can build in the Console. Each one connects several tools, shows the settings for every step, and includes a full workflow you can paste into the [JSON editor](/workflows/json-editor).

They are for people who have read the [Integrations quickstart](/integrations/quickstart) and want to see how the pieces fit together. Connector pages describe single tools. These guides show how to combine them to get a real result.

## What you need first

<Steps>
  <Step title="Know the basics">
    Read [Connections](/integrations/connections) and [MCP instances](/integrations/mcp-instances). A **connection** stores the login for another service. An **MCP instance** is that service's tools, installed in your workspace. An `mcp` step in a workflow uses one tool from an instance.
  </Step>
  <Step title="Set up the tools">
    Each guide lists the connectors it needs. For each one, open **MCP**, click **Add connectors**, click the connector and then **Add to workspace**, then connect it on **Instance config**.
  </Step>
  <Step title="Open Workflow Studio">
    Build in [Workflow Studio](/workflows/studio). If you prefer raw JSON, use the [JSON editor](/workflows/json-editor) and the [JSON cookbook](/workflows/json-schema-cookbook).
  </Step>
</Steps>

## Things that apply to every guide

- **Tool names are exact.** A step's `tool_name` must match a tool published by the connector, such as `postgres_query` or `resend_send_email`. The connector page lists the tools.
- **Models.** Guides use `gpt-4o` or `gpt-4o-mini` as examples. Use any model your workspace can use, and see [LLM providers](/ai/llm-providers).
- **Your instance.** In the pasted JSON, replace each `REPLACE_…_INSTANCE` placeholder on an `mcp` step with the id of your own MCP instance.
- **Saving and running.** Your changes are saved to the workflow's **Live** copy, and runs and triggers use it by default. You only need to **Publish** when you want a frozen version. See [Workflow Studio](/workflows/studio#live-copy-and-published-versions).
- **Test first.** Use a manual run with sample input before you connect a real trigger. See [Dry run](/workflows/dry-run).

| Pattern | Guides using it |
|---------|-----------------|
| Webhook, then store, then notify | Form digest, lead sync |
| External event, then look up, then message | Shopify → WhatsApp |
| Conversation, agent, person, agent | WhatsApp customer chat |
| Fetch, LLM, human approval, action | GitHub PR review |
| Schedule, query, summarize, email | Postgres weekly report |
