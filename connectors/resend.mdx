---
title: Resend connector
description: Send transactional and broadcast email through Resend, and manage contacts, domains, and templates, from AgentRuntime workflows.
---

[Resend](https://resend.com) is an email service for sending email from your own domain. The **resend** connector lets workflow steps send single or batch emails, run broadcast campaigns, and manage contacts, segments, topics, domains, templates, webhooks, and automations in your Resend account.

Typical uses: tell your team when a workflow finishes, email a customer a receipt or report, and keep a Resend contact list in step with another system.

## Prerequisites

- A Resend account.
- A sending domain verified in Resend, and a sender address on it (for example `notifications@yourdomain.com`). Resend also offers a test sender for early experiments; see Resend's own documentation for its limits.
- A Resend API key. A key with sending access is enough for the email tools. Tools that manage contacts, domains, templates, webhooks, and API keys may need a key with full access.
- The **project_contributor** role or higher in your workspace.

## Connect in AgentRuntime

<Steps>
  <Step title="Get a Resend API key">
    In the Resend dashboard, add and verify your sending domain (Resend shows the DNS records to create). Then open **API Keys**, create a key, and copy it. Resend shows the full key only once.
  </Step>
  <Step title="Create a connection">
    Open **Connections** in the [Console](https://console.agentruntime.io) and click **New custom connection**. Enter a **Display name** (for example `Resend`). Under **Credentials**, add one row per setting, using **Add field** for more rows:

    - **Key** `api_key`, **Value** your Resend API key.
    - **Key** `from_email`, **Value** your verified sender address, for example `notifications@yourdomain.com`.

    Click **Save**. The dialog also asks who can use the connection; choose the option that fits your team.
  </Step>
  <Step title="Add the resend MCP instance">
    Open **MCP**, click **Add connectors**, find **resend**, and add it to your workspace. Open the instance, and on **Instance config** create or open a profile, choose your connection in the **Connection** picker, set the profile **Status** to **Active**, and click **Save**, then **Use this profile for workflows**.
  </Step>
  <Step title="Smoke test">
    In **Workflow Studio**, add a connector tools step that calls `resend_send_email` to your own address (see the example below) and run it. A result with an `email_id` and status `queued` means Resend accepted the message.
  </Step>
</Steps>

See [Authentication](/integrations/authentication) for how connections are attached to MCP instances.

## What you can build

- **Workflow completion alerts.** After a run succeeds or fails, call `resend_send_email` with the run name and a short summary.
- **Weekly digest.** Query your data with the [Postgres connector](/connectors/postgres), let an LLM step write the summary, then send it with `resend_send_email`.
- **Welcome and onboarding email.** When a new sign-up arrives, call `resend_create_contact` to add them to Resend and `resend_send_email` to greet them.
- **Campaigns.** Create a broadcast with `resend_create_broadcast` and send or schedule it with `resend_send_broadcast`, after a **human** step approves the content.

### Key parameters

- `resend_send_email`: `to` (required, **a list** of addresses), `subject` (required), and `text` and/or `html`. The sender is always your configured `from_email`; it is not a tool argument. If you give neither `text` nor `html`, the body is `(empty body)`.
- `resend_send_batch_emails`: `emails` (required), a list of 1 to 100 objects. Each has `to` (list), `subject`, `text`, and optionally `html`, `from` (defaults to your `from_email`), `reply_to`, `cc`, `bcc`, `scheduled_at`, `tags`, and `topic_id`.
- `resend_list_audiences`: optional `page_size` (default 20, maximum 100). It returns audience names and a count only, not IDs.
- `resend_create_broadcast`: `name`, `segment_id`, `subject`, and `text` are required; `html`, `preview_text`, `from`, and `reply_to` are optional. `resend_send_broadcast` takes `broadcast_id` and an optional `scheduled_at`.
- `resend_create_contact`: `email` is required; `first_name`, `last_name`, `unsubscribed`, `properties`, `segment_ids`, and `topics` are optional.

Most management tools return the full Resend response as JSON text in `raw_json`.

## Example

Email yourself a run summary:

```json
{
  "id": "notify-complete",
  "type": "mcp",
  "name": "Email run summary",
  "instance_id": "YOUR_RESEND_INSTANCE_ID",
  "tool_name": "resend_send_email",
  "tool_args": {
    "to": ["ops@example.com"],
    "subject": "Workflow finished: {{input.workflow_name}}",
    "html": "<p>Run <strong>{{input.run_id}}</strong> completed.</p>"
  },
  "timeout_s": 30
}
```

In Studio you pick the instance and tool from lists, and Studio fills in `instance_id`.

## Configuration

These are the settings on the instance's config profile. When you use a connection, give its credential rows the same key names.

| Key | Required | Description |
|-----|----------|-------------|
| `api_key` | Yes | Resend API key. |
| `from_email` | Yes | Sender address used as From for `resend_send_email`. Must be on a verified domain. |
| `api_base` | No | Resend API base URL. Default `https://api.resend.com`. |
| `audience_id` | No | Default audience ID for tools that do not take an audience argument. |

## Troubleshooting

| Issue | Fix |
|-------|-----|
| `resolved config is missing api_key` or `missing from_email` | The active profile does not have that setting. Add the `api_key` and `from_email` rows to the connection and check the profile is **Active**. |
| `Resend API error 403` when sending | Usually the `from_email` domain is not verified in Resend, or the key lacks permission. Finish DNS verification and check the key's access level. |
| `Resend API error 401` | The API key is wrong or was deleted. Create a new key and use **Rotate** on the connection. |
| `Resend API error 429` | Resend's rate limit. The connector retries a few times; space out large loops. |
| Email lands in spam | Set up SPF, DKIM, and DMARC for your sending domain in your DNS provider. |
