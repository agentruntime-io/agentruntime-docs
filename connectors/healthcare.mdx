title: Healthcare connector
description: A demo connector with made-up patient data, for prototyping and testing clinical-style workflows.
---

The **healthcare** connector returns **mock data only**. Its tools imitate patient lookup, history, diagnosis suggestions, medication checks, scheduling, and notifications so you can prototype and demo a clinical-style workflow. It is not connected to any real system, and its answers are not medical advice.

## Prerequisites

- No credentials. The connector needs no keys and no outside account.
- The **project_contributor** role or higher in your workspace, which lets you manage connections and MCP instances. See [Roles and permissions](/platform/roles-permissions).
- A non-production project. Do not put real patient data into a workflow that uses this connector.

## Connect in AgentRuntime

<Steps>
  <Step title="Add the connector to your workspace">
    Click **MCP** in the sidebar, then **Add connectors**. Find **Healthcare** in the **App catalog**, select it, and click **Add to workspace**. The instance now appears on the **MCP connectors** page. See [MCP instances](/integrations/mcp-instances).
  </Step>
  <Step title="Make sure a profile is active">
    Open the new instance to reach **Instance config**. The connector needs no credentials, but workflows use the profile marked active. If none exists, click **New profile**, set **Status** to **Active — can be used in workflows**, click **Save**, and then click **Use this profile for workflows**.
  </Step>
  <Step title="Test it">
    In **Workflow Studio**, add the `healthcare_patient_lookup` tool from your **Healthcare** instance (use **Browse platform MCP** if it is not listed), fill in its arguments, and run the workflow. A successful step means the connection works. Use the sample ID `PT-001`.
  </Step>
</Steps>

<Warning>
  This connector is for demos and testing. The data is invented, the results are fixed examples, and nothing is sent to real patients or providers.
</Warning>

## What you can build

- **Demo flows.** Walk a chat or workflow through lookup, a mock diagnosis, finding an appointment slot, and booking it.
- **Failure testing.** Set `_fail` to `true` or `_latency_ms` to a number on any tool to see how your workflow handles errors and slow responses.
- **Approval prototypes.** Put a **Human** step before `healthcare_medication_prescribe` to design an approval screen.
- **Blueprint.** Build the workflow shape here, then swap in a real integration later.

## Tools

Every tool also accepts the optional `_latency_ms` (simulated delay in milliseconds) and `_fail` (set `true` to force an error) arguments. They are not listed in the table.

The sample patient IDs are `PT-001`, `PT-002`, and `PT-003`. The scheduling tool returns the sample slot IDs `SLOT-001`, `SLOT-002`, and `SLOT-003`.

| Tool | Access | What it does | Required arguments |
|------|--------|-------------|--------------------|
| `healthcare_diagnosis_analyze` | Read | Run a mock differential diagnosis analysis for a patient. | `patient_id`, `symptoms`, `medical_history` |
| `healthcare_generate_summary` | Write | Generate a mock patient visit summary from visit context. | `patient_id`, `visit_notes`, `diagnosis_summary`, `prescription_summary` |
| `healthcare_medication_check` | Read | Check mock drug interactions and allergy conflicts for a proposed medication. | `patient_id`, `proposed_medication`, `current_medications` |
| `healthcare_medication_prescribe` | Write | Create a mock prescription record for a patient. | `patient_id`, `medication`, `dosage`, `frequency`, `duration`, `prescribed_by` |
| `healthcare_notification_send` | Write | Send a mock patient or provider notification. | `recipient_id`, `channel`, `subject`, `message` |
| `healthcare_patient_history` | Read | Return mock clinical history entries for a patient. | `patient_id` |
| `healthcare_patient_lookup` | Read | Look up a mock patient record by patient ID. | `patient_id` |
| `healthcare_scheduling_book` | Write | Book a mock appointment for a patient in a selected slot. | `slot_id`, `patient_id`, `reason` |
| `healthcare_scheduling_find_slot` | Read | Find available mock appointment slots for a provider and department. | `provider`, `department`, `preferred_date`, `duration_minutes` |

## Example

Look up a sample patient.

```json
{
  "id": "lookup",
  "type": "mcp",
  "name": "Look up sample patient",
  "tool_name": "healthcare_patient_lookup",
  "tool_args": {
    "patient_id": "PT-001"
  },
  "timeout_s": 30
}
```

## Configuration

This connector has no configuration keys.

## Troubleshooting

| Problem | What to do |
|---------|------------|
| Patient not found | Use one of the sample IDs: `PT-001`, `PT-002`, or `PT-003`. |
| Unexpected diagnosis or medication output | The output is fixed sample data, not clinical advice. |
| Need to test an error path | Pass `_fail` set to `true` on the tool. |
