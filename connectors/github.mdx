title: GitHub connector

The **github** connector lets workflows work with GitHub: read and write issues and pull requests, browse and change files, follow Actions runs, search code, and more. Use it to triage issues, summarize pull requests, post status comments, or keep a changelog up to date.

## Prerequisites

- A GitHub account with access to the repositories you want to automate.
- A GitHub **personal access token** (classic or fine-grained) that can reach those repositories.
- The **project_contributor** role or higher in your workspace, which lets you manage connections and MCP instances. See [Roles and permissions](/platform/roles-permissions).

## Connect in AgentRuntime

<Steps>
  <Step title="Create a GitHub token">
    In GitHub, open **Settings**, then **Developer settings**, then **Personal access tokens**, and generate a token. For a fine-grained token, select the repositories you will use and grant only the permissions your workflow needs (for example read access to contents and pull requests, and write access to issues if you will comment). Copy the token.
  </Step>
  <Step title="Add the connector to your workspace">
    Click **MCP** in the sidebar, then **Add connectors**. Find **GitHub** in the **App catalog**, select it, and click **Add to workspace**. The instance now appears on the **MCP connectors** page. See [MCP instances](/integrations/mcp-instances).
  </Step>
  <Step title="Add your credentials to a profile">
    Open the new instance to reach **Instance config**. Under **Profiles for this connector**, click **New profile**, enter a **Display name**, and on the **Type secrets on this screen** tab fill in `github_api_token` (your token). Set **Status** to **Active — can be used in workflows** and click **Save**. Then click **Use this profile for workflows**.
  </Step>
  <Step title="Test it">
    In **Workflow Studio**, add the `github_get_me` tool from your **GitHub** instance (use **Browse platform MCP** if it is not listed), fill in its arguments, and run the workflow. A successful step means the connection works. This tool has no arguments and returns the user the token belongs to.
  </Step>
</Steps>

<Note>
  To reuse the same credentials in more than one profile, save them first under **Connections** → **New custom connection**, using the exact key names from [Configuration](#configuration), then choose **Use a saved connection** on the profile instead.
</Note>

## What you can build

- **Pull request helper.** `github_list_pull_requests` and `github_pull_request_read` feed an LLM step that writes a review summary, which `github_add_issue_comment` posts.
- **Issue triage.** `github_list_issues` finds new issues, an LLM step classifies them, and `github_issue_write` sets labels and assignees.
- **Changelog draft.** `github_compare_commits` between two tags feeds an LLM step, and `github_create_or_update_file` commits the notes (add a **Human** approval step first).
- **CI watcher.** `github_actions_list` and `github_actions_get_job_logs` collect failing runs so a workflow can open an issue or notify the team.

## Tools

The **Required arguments** column lists the fields the tool's input schema marks as required. Some of them are optional in practice; if you have nothing to set, pass an empty value such as `""`, `[]`, `{}`, or `false`.

Several tools combine related actions behind a `method` argument (for example `github_issue_read`, `github_issue_write`, and `github_pull_request_read`). The tool's input schema lists the allowed `method` values.

Tools marked **Delete** remove data and may be irreversible.

## Example

Comment on a pull request or issue. `number` is the issue or pull request number.

```json
{
  "id": "pr-comment",
  "type": "mcp",
  "name": "Post review summary",
  "tool_name": "github_add_issue_comment",
  "tool_args": {
    "owner": "your-org",
    "repo": "your-repo",
    "number": "{{input.pr_number}}",
    "body": "Automated review complete.\n\n{{steps.llm-summary.result.text}}"
  },
  "depends_on": [
    "llm-summary"
  ],
  "timeout_s": 30
}
```

## Troubleshooting

| Problem | What to do |
|---------|------------|
| `401` "Bad credentials" | The token is wrong, expired, or revoked. Create a new one and update the profile. |
| `403` or `404` on a repository | The token cannot see that repository. For a fine-grained token, add the repository and the needed permission. |
| Empty search results | GitHub rate-limits search and can lag on new content. Narrow the query and retry later. |
| Want to start a workflow from a GitHub event | See [Inbound webhooks](/integrations/inbound-webhooks). |
