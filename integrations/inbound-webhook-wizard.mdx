title: Inbound webhook wizard
description: Step-by-step guide to creating a signed inbound webhook in Workflow Studio, Settings, or Autopilot chat.
---

This page walks you through the Console screens for creating an inbound webhook. It is for anyone who wants an outside system (a payment provider, a CI job, your own backend) to start a workflow. For how senders must sign requests, see [Inbound webhooks](/integrations/inbound-webhooks).

## Before you start

- A **saved** workflow in Workflow Studio. If you have not saved it, the **Inbound** tab says "Save the workflow to manage inbound webhooks."
- The **project_contributor** role or higher. Other roles see "Contributors can add inbound webhooks."
- At least one API key (personal access token) under **Settings → API keys**. The webhook uses it as the identity its runs execute as. See [API authentication](/api/authentication).

## Create a webhook in Workflow Studio

<Steps>
  <Step title="Open the workflow">
    Open your workflow in **Workflow Studio**.
  </Step>
  <Step title="Open the Inbound tab">
    In the workflow configuration panel, open **Inbound**. It lists the webhooks for this workflow only.
  </Step>
  <Step title="Name it">
    Enter a **Label**, for example `shopify-orders`. The label shows in the list so you can recognize the webhook later.
  </Step>
  <Step title="Choose the purpose">
    Under **Webhook purpose**, keep **Start workflow run** for the usual case: each request starts a run. The other option, **Append to agent inbox (mid-turn)**, sends a message into an agent run that is already in progress.
  </Step>
  <Step title="Choose the sender type">
    Under **Vendor adapter**, leave **Direct caller only** if your own code or a CI job will call the webhook. Pick a listed vendor adapter if the service (for example GitHub or Telegram) registers the webhook itself. Then select the **Connection** that holds that vendor's credentials.
  </Step>
  <Step title="Choose which version runs">
    Under **Runs**, choose whether requests run your latest saved edits (**Live**) or the newest published version (**Last published**).
  </Step>
  <Step title="Choose the automation API key">
    Under **Automation API key**, pick the key the runs should execute as. If the Console cannot read the key automatically, a field appears where you paste the `pat_…` secret once.
  </Step>
  <Step title="Create it">
    Click **Create subscription**. A dialog titled **Signing secret (copy now)** appears.
  </Step>
</Steps>

You should see two copy fields: **Signing secret** and **Ingress URL (start run)**. For the agent inbox purpose you also see **Agent inbox URL (mid-turn append)**. Copy them now. The signing secret cannot be shown again. Store it in your secrets manager.

## See and remove webhooks across the workspace

Open **Settings** and the **Inbound webhooks** tab. It lists every webhook in the workspace. You can delete one with the delete button and confirm in **Delete inbound subscription?**. Create new webhooks from a workflow's **Inbound** tab, not here.

## Create a webhook from Autopilot chat

In Autopilot chat, ask something like "Create an inbound webhook for this workflow". Autopilot shows an inbound webhook card.

1. Open a saved workflow in Workflow Studio first. Without one, Autopilot asks you to open a saved workflow.
2. In the card, set the name and **Automation API key**, then create the webhook.
3. Copy the signing secret and ingress URL from the result. The card also shows an example `curl` command.

## After creating the webhook

| Item | What to know |
|------|--------------|
| **Signing secret** | Shown once. Use it to sign every request. |
| **Ingress URL** | The address senders POST to. |
| **Automation API key** | Stored with the webhook. Senders do not send it. |

Next, send a signed test request, as described in [Inbound webhooks](/integrations/inbound-webhooks#verify-signatures). Check **Runs** to see the run start.

## Common problems

| Problem | What to do |
|---------|------------|
| The **Inbound** tab is empty or disabled | Save the workflow first, and make sure you have the contributor role. |
| The **Automation API key** list is empty | Create a key under **Settings → API keys**, then come back. |
| Requests return `400` | Check the `X-Agentruntime-Signature` and `Idempotency-Key` headers. See [Inbound webhooks](/integrations/inbound-webhooks). |
| You lost the signing secret | Delete the webhook and create a new one. |
