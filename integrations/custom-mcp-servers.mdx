title: Custom MCP servers
description: Register an MCP server that you run yourself and use its tools in your workflows.
---

Most teams add connectors from the catalog. If you run your own **MCP server** (a service that exposes tools over the Model Context Protocol), you can register it and use its tools in workflows like any other connector. This page is for developers or admins who operate such a server.

## Before you begin

- The **project_contributor** role or higher (MCP write permission).
- An MCP server reachable at a URL, using streamable HTTP, for example `https://tools.example.com/mcp`.
- At least one tool exposed by the server. Registration stops with "No tools discovered" if the server returns none.

## Register the server

<Steps>
  <Step title="Open the catalog">
    Go to **MCP** and click **Add connectors**. The **App catalog** opens.
  </Step>
  <Step title="Start registration">
    In the left column, click **Add connector** (not **Add to workspace**). The **Add MCP connector** dialog opens.
  </Step>
  <Step title="Fill in the form">
    - **Name** — required, for example `Resend MCP`.
    - **MCP URL** — required. The address of your server's MCP endpoint.
    - **Bridge vendor** — leave on **Auto-detect from URL** unless you know you need another option: **Grafana (URL + token headers)**, **Google / Gmail (bearer token)**, or **Custom (no auth mapping)**.
    - **Description (optional)**.

    Click **Register →**.
  </Step>
  <Step title="Watch the progress">
    The dialog lists six steps: **Register server**, **Discover tools**, **Review catalog**, **Publish & activate**, **Validate connector**, and **Add workspace instance**. After discovery you can review the tools. The dialog continues by itself after a few seconds; click **Hold** to pause and look at the list.
  </Step>
  <Step title="Open the instance">
    When it finishes you see **Open instance →** and **Open server** links. Open the instance to attach credentials if your server needs them.
  </Step>
</Steps>

You should now see the instance on **MCP connectors**, under your own MCP servers. Use it in **Workflow Studio** with an MCP step, as described in [MCP instances](/integrations/mcp-instances).

If registration stops partway, the server appears under **Setup incomplete** on the **MCP connectors** page. Click **Manage setup** to fix the URL and finish discovery and publishing.

## Credentials

Whether your server needs credentials depends on the server.

- **Credentials stored in AgentRuntime:** save them as a [connection](/integrations/connections) and attach it to the instance's active profile, as with any connector. For Grafana, choose the **Grafana** bridge vendor; the instance then asks for the Grafana URL and a service account token.
- **Your server checks its own tokens:** there may be nothing to attach. Run a test workflow to confirm.

Do not put secrets in workflow graphs or scripts.

## API

You can also manage servers through the API. These routes require MCP write (or read, for discovery) permission:

| Action | Request |
|--------|---------|
| Create a server | `POST /v1/mcp/servers` |
| Discover tools | `GET /v1/mcp/servers/{id}/discover` |
| Publish a version | `POST /v1/mcp/servers/{id}/versions` |
| Run validation | `POST /v1/mcp/servers/{id}/validate` |
| Add an instance | `POST /v1/mcp/instances` |

The Console wizard is the easiest route because it also sets up routing for you. See [API examples](/api/examples#register-a-custom-mcp-server) and the [API reference](/api/reference#mcp).

## Common problems

| Problem | What to do |
|---------|------------|
| "No tools discovered" | Check the **MCP URL**, that the server is running, and that it lists at least one tool. |
| A validation check fails | Open `/mcp/{server_id}/validate` and click **Run checks**. Each check shows its message. |
| Tools are missing in Workflow Studio | Make sure the instance exists and has an **active** profile. Reload the workflow. |
| 401 or 403 at run time | Attach the right connection to the profile, or fix your server's own authentication. |
