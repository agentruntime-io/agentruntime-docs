title: Run setup

**Run setup** controls how a workflow starts. You set the **starting input** (the values your steps read as `{{input.*}}`) and, optionally, which steps the run starts from.

**Who this is for:** anyone who runs a workflow by hand or sets up a schedule or webhook for it.

**What you will do:** start a run with your own input, and save the values as defaults.

## Open Workflow setup

In [Workflow Studio](/workflows/studio), click **Setup** in the toolbar. The **Workflow setup** dialog has these tabs:

| Tab | What it is for |
|---|---|
| **Manual** (Defaults & run) | Set the starting input for runs you start by hand |
| **Inbound** (Webhooks) | Start runs from outside systems with signed webhooks |
| **Events** (Platform) | Start runs when a platform event happens (Embedded Connect) |
| **Cron** (Schedules) | Start runs on a schedule |
| **Sessions** (Per conversation) | One run per conversation. See [Conversation sessions](/workflows/conversation-sessions). |
| **API** (PAT run) | A ready-made request to start the workflow with an API key |
| **Apps** (Used by) | Lists the apps that use this workflow |

The **Manual** tab's footer has **Preview JSON**, **Cancel**, and **Save defaults**. The other tabs only have **Close**, and remind you that **Save defaults** and **Run** belong to the **Manual** tab. The dialog has no **Run** or **Dry-run** button of its own: use **Run** and **Dry-run** in the Studio toolbar.

## Start a run by hand

<Steps>
  <Step title="Open the Manual tab">
    Click **Setup**, then **Manual**.
  </Step>
  <Step title="Choose where the run starts">
    Under **Entry step**, you see the step or steps the run starts from. Unchecked entry steps are left out when the trigger fires. To leave a step out of every run, disable it on the canvas instead (**Step enabled**). **Run as** is **Workspace** by default: one run for the whole workspace. The other choices are for runs on behalf of Embedded Connect end users. See [Triggers and run identity](/workflows/trigger-run-identity).
  </Step>
  <Step title="Type the starting input">
    Under **Starting input**, each field of the entry step has a checkbox and a box for its value. In the demo workflow there is one field, **payload**, which takes JSON or text. Fields you leave empty fall back to the step's own settings on the canvas at run time. A field you edit shows a **Changed** badge.
  </Step>
  <Step title="Run">
    Close the dialog and click **Run** in the Studio toolbar.

    You should see the new run appear under **Run logs and metrics**.
  </Step>
</Steps>

**Run** does not change your saved defaults. If you click **Cancel** after typing, Studio asks **Unsaved setup changes** and offers **Keep editing**, **Discard changes**, or **Save defaults**.

## Save defaults

**Save defaults** stores the entry step choice and starting input so the forms open pre-filled next time. The tab says it plainly: "Saved defaults prefill this form only." Schedules, platform events and inbound webhooks use the values stored on their own settings when you create them, not the saved defaults.

## Schedules, webhooks, and the API

Each of these keeps its own start values:

- **Cron**: the schedule has the same entry step and starting input as **Manual**, saved on the schedule when you click **Add schedule**. It also asks which version to run (**Runs**) and which **Automation API key** to run as.
- **Inbound**: you can save fixed start values on a webhook. The data in each request is merged with them, and the request wins if both set the same value.
- **API**: send the complete start input in `trigger_payload` (and `trigger_steps` for per-step values). See [External triggers](/workflows/external-triggers).

## What the input becomes

Whatever you type under **Starting input** is available to the steps as `{{input.<field>}}`. Per-step values are read by that step. Use [Dry-run](/workflows/dry-run) to check that every `{{input.*}}` your workflow reads has a value.

## Common problems

| Problem | What to try |
|---|---|
| **Run** is greyed out in the toolbar | The canvas is empty, or your role cannot run workflows. See [Workflow Studio](/workflows/studio#common-problems). |
| A schedule ignores the values you saved with **Save defaults** | Expected. A schedule uses the values saved on the schedule itself. |
| A field is empty at run time | Check that it is included in the form, or set on the step in the canvas. |
