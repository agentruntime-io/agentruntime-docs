A **run** is one execution of a workflow. This page explains how runs start, what the run panel shows, how to control a run, and how to read step statuses.

**Who this is for:** anyone who runs or supports workflows.

## Start a run

| From | How |
|---|---|
| **Workflow Studio** | Click **Run**. It runs your **Live** copy with the input from **Workflow setup**. |
| **API** | `POST /v1/workflows/{id}/command` with `"command": "start"`. See the [API reference](/api/reference). |
| **Schedule** | A cron schedule you add in **Workflow setup → Cron** |
| **Inbound webhook** | An outside system sends a signed request. See [Inbound webhooks](/integrations/inbound-webhooks). |
| **Platform event** | **Workflow setup → Events**, for Embedded Connect events |
| **Conversation** | A message from a contact joins or starts a [conversation session](/workflows/conversation-sessions) |
| **Autopilot** | Ask Autopilot in Chat to run a workflow by name |

Each trigger chooses which version it runs: **Live**, **Last published**, or a fixed version. See [Live copy and published versions](/workflows/studio#live-copy-and-published-versions). A run keeps the version it started with, even if you edit the workflow later.

## Watch a run

Open the workflow in Workflow Studio and expand **Run logs and metrics** at the bottom. Pick a run from the **Runs** list on the left (filter it with **All**, **Running** or **Failed**). The run panel has these tabs:

<Frame caption="The Events tab of a finished run: one row per step, with the step's output when you expand it">
  <img src="/images/workflows/runs-events-tab.png" alt="The run panel for a successful run with the Events, Timeline, Context, Full Logs and Dry Run tabs. The Events tab lists three steps, Draft the summary, Approve the refund and Record the decision, each with a green check and its start and end time. Record the decision is expanded and shows its output" />
</Frame>

- **Events**: a log of every step: started, tool result, model output, failure, pause. It updates live while the run is active.
- **Timeline**: a bar for every step so you can see where time went. See [Execution timeline](/workflows/execution-timeline).
- **Context**: the run's details and a graph of the steps in the order they ran.
- **Full Logs**: the complete log lines for the run.
- **Dry Run**: the latest [dry-run](/workflows/dry-run) result for the current canvas (not a replay of the selected run).

For a step that ran an agent or a model, click **Watch LLM** to replay what it generated.

Runs that wait for a person also appear in [Command Center](/workflows/command-center), which lists runs across the whole workspace.

## Control a run

In Studio, use the buttons next to **Run** while a run is selected. In Command Center, use the buttons on the run's row. The API takes the same commands.

| Control | Effect |
|---|---|
| **Pause** | No new steps start. Steps already running can finish. |
| **Resume** | Continue a paused run. |
| **Stop** | End the run. Options: **Force stop** (the main button), **Stop immediately**, **Stop gracefully**. |

- **Stop immediately** and **Force stop** cancel tool calls in flight. Model calls are cancelled on a best-effort basis.
- **Stop gracefully** lets running steps finish and never starts the rest. The run ends as **Stopped**.
- A stopped run cannot be resumed. Start a new run instead.

In the API, `stop` takes `params.mode`: `immediate` (default) or `graceful`.

## When a step fails {#failure-handling}

When a step fails, the run **fails** at once and cannot be resumed. The canvas and the **Events** tab show what happened to every step, so you can see which step caused it and which were only collateral:

| Status shown | When |
|---|---|
| **Failed** | The step that caused the run to fail. Read its error in **Events**. |
| **Cancelled** | The step was running at the same moment (for example a parallel model call) when another step failed |
| **Skipped · Blocked** | The step never started because a step it needs failed |
| **Success** | The step finished before the failure. Its output is still in the run's **Context**. |

For example: branch A fails because a credential is missing. Branch B was still calling a model, so it shows **Cancelled**. The step that joins A and B shows **Skipped · Blocked**.

Other skip reasons you may see in **Events**: **Disabled** (the step is switched off), **Excluded this run** (you left it out in setup), **Approval rejected**, **Out of scope** (see [Autonomous episodes](/workflows/autonomous-episodes)).

<Note>
  A step **Cancelled** by a failure is not the same as a run you stopped yourself. A stopped run shows **Stopped by operator**.
</Note>

Fix the cause (model, credential, tool arguments), then start a **new run**. See [Run recovery](/workflows/run-recovery). The events behind these statuses are listed in the [API reference](/api/reference#run-event-types).

## Replay a run

There is no separate replay command. Open the run in Studio and read **Events**. Through the API, page through `GET /v1/workflows/{id}/runs/{runID}/events`.

## Analytics

The **Analytics** page shows workspace-wide numbers: live and recent runs, success rate, steps run, credits used, and usage over time. See [Analytics](/platform/analytics).

## Credits

Model tokens, tool calls, and workflow steps use credits according to your plan. Usage appears on the Analytics page and in billing. See [Billing and credits](/platform/billing-and-credits).

## Common problems

| Problem | What to try |
|---|---|
| The run shows **Paused** | It may be waiting for a person. Open [Command Center](/workflows/command-center) and answer the task. |
| The run is **Running** but nothing changes | Open **Events** and read the last step. A slow tool or model is the usual cause. See [Troubleshooting](/platform/troubleshooting). |
| **Insufficient credits** | Top up in billing, then start a new run. |
