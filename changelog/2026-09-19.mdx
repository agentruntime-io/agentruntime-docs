**Platform v0.3.2** ships batch-agent fan-out for connected workflows: each list item can invoke a published child workflow with its own run id, iteration timeouts, and parallel limits.

## Workflow Studio and runs

**Batch agent template** — start from **Batch agent (one run per item)** to wire a for_each loop with an inner Sub-workflow step. Publish the child workflow first, then set its id on the inner step.

**for_each fan-out** — add a Sub-workflow step inside a for_each or while body to run a child workflow once per item. When **Wait for child** is on, the parent collects `child_run_id` and terminal output per iteration.

**Iteration budgets** — cap parallelism, per-item timeouts, and error policy (fail fast vs continue on error) on the loop step. Set inner Sub-workflow timeouts at or below the loop item timeout when both apply.

**Loop body drag** — drag **Sub-workflow** from the built-in palette onto a loop body region instead of using JSON import only.

## Operate and approvals

**Child workflow approvals** — if a child run pauses on a human task, the parent wait step keeps polling until the child completes or times out. Open the child run from Tasks to approve.
