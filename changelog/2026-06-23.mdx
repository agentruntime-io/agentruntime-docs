**Platform v0.2.1** builds on [v0.2.0](/changelog/2026-06-20) (session workflow and Continue on limit).

Deploy requires coordinated schema migrations before rolling services — chat-service **`000008`–`000010`** (lifecycle columns, execution lanes, composer drafts) and wheelhouse **`000024`–`000026`** (accountability columns). Operators should follow the internal lifecycle and UE merge runbooks.

## Workspace Chat

**Message queue** — if a turn is still running, new user messages wait server-side with `queued` status and dispatch when the lane frees up, instead of failing or spawning duplicate runs. Users can cancel queued messages before dispatch.

**Composer drafts** autosave unsent text scoped to tenant, user, conversation, and optional thread root — pick up where you left off on another device.

**Archive** moves conversations out of the active inbox while preserving history and recording who archived and when.

**Reload recovery** and **Continue on limit** sidebar UX work together: after refresh, Space hydrates the Continue CTA from persisted agent payload and turn-status metadata.

**Execution lanes** bind each copilot starter (DM vs agent room) to its own workflow binding so parallel chat surfaces do not share run state incorrectly.

## Console

**Resend verification email**, clearer auth error copy, **password change**, and centralized session refresh. Auth login mode (`ropc` / `oauth` / `gateway`) is configurable per environment — align Console INI with BFF settings after deploy.

## API and permissions

Public BFF routes now enforce **Cedar-backed permissions** aligned with membership capabilities and PAT scopes. If an integration suddenly receives `403`, verify the token's scopes and the user's project or tenant permissions — not only legacy role names.

OAuth profile updates, password change, PAT creation, MCP execute, onboarding, and billing handlers all participate in the same permission model.

**Lifecycle accountability** gives admins a clearer audit trail: who archived a conversation, who deleted a message, and when entity state changed — without relying on boolean `is_deleted` flags.

## Workflows and runs

Operators validating this release should run the UE merge acceptance gates on a dev stack before production cutover. Chat observe streams continue to emit tool-round and limit-reached events for live triage.
