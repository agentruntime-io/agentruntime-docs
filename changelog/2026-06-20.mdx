**Platform v0.2.0** unifies agent and workflow execution. It includes the June pre-merge bridge (contacts, Work route, Space ↔ work) and the unified execution baseline below.

## Workspace Chat and Console

**Session workflow** is the headline UE change: send multiple messages in Autopilot DM or an agent room and the platform keeps one workflow **run** for the conversation. Command Center and run observe show the same run ID across turns.

**Continue on limit** ships in v0.2.0 for both Console and Workspace Chat. When a turn stops at the configured tool-round cap, the UI shows an awaiting state and a **Continue** control; the orchestrator extends the slice and the same run resumes. Reload the page mid-stream and turn status restores from the API.

The pre-merge bridge adds **contacts** (user and workspace), a **tablet layout**, and **work integration** so you can jump to tasks and files from Space. Console gains a dedicated **Work** route and clearer **MCP bridge** setup for project tool wiring.

Console Autopilot shows limit/paused run visibility in the **Execution panel**; Space shows a status indicator and blocks the composer until Continue is resolved.

## Workflows

Published workflows with **`agent_call`** steps use the in-process runtime loop. Handoffs, MCP tool rounds, episode pause/resume, and **`chat_agent`** alias resolution behave consistently in Workflow Studio runs and in chat-bound session workflows.

Connectors on this baseline match the Go MCP SDK v0.1.5 line — tool schemas and auth flows align with Platform MCP expectations.
