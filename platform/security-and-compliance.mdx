This page is for builders and for people evaluating AgentRuntime for their company. It summarizes how access and secrets are handled and what to consider for regulated data.

It is an overview, not a contract. Binding terms are in the [legal policies](#legal-policies).

## How people and systems get in

| Way in | How it is protected |
|--------|--------------------|
| **Console** | Sign in with email and password (email verification required) or with Google. You stay signed in with a browser session. |
| **API and Platform MCP** | Personal access tokens (API keys) with scopes. They can never do more than the person who created them. |
| **Inbound webhooks** | Each request must carry a signature and an automation key. See [Inbound webhooks](/integrations/inbound-webhooks). |

Always call AgentRuntime through `https://api.agentruntime.io`.

## Workspace and project separation

| Layer | What it separates |
|-------|-------------------|
| **Workspace** | Members, billing, and workspace-wide connections and tools. Workspaces cannot see each other. |
| **Project** | Workflows, and optionally agents, connections and webhook subscriptions. Private projects are visible only to their members. |
| **Roles** | What each person can do. See [Roles and permissions](/platform/roles-permissions). |

Workspace admins can also restrict who may join: require invites, allow only verified company email domains, and review access requests. See [User management](/platform/user-management). Admin actions such as invites, membership changes and access policy changes are recorded in **Settings → Audit log**.

## Secrets and credentials

| What | Where you manage it |
|------|---------------------|
| Tool logins and API keys | **Connections** |
| AI model provider keys | **Providers** |
| API keys for scripts and CI | **Settings → API keys**. The secret is shown once. |
| Webhook signing secrets | Shown once when you create a subscription |
| Workspace secret paths | **Vault** (workspace admins) |

Do not put secrets in workflow graphs, Lua scripts or code that runs in a browser. Use connections and provider keys instead.

If a key may be exposed, revoke it in the Console, review your recent runs, and create a replacement.

## How your data is handled

| Data | What to know |
|------|--------------|
| **Workflows** | Stored per project. Published versions cannot be edited. |
| **Runs** | Run history shows each step's events so you can troubleshoot and approve work in [Command Center](/workflows/command-center). |
| **AI prompts** | Sent to the model provider you set up. Review that provider's terms. |
| **Tool calls** | Run against the connections you linked. The third-party service's own policies apply. |
| **Billing records** | Kept separately for each workspace. |

Memory features are in preview. See [Memory](/ai/memory) and [Feature availability](/platform/feature-availability).

## Compliance guidance

AgentRuntime is not certified for regulated workloads out of the box. Check your own requirements before using it with sensitive data.

| Topic | Guidance |
|-------|----------|
| **Health data (HIPAA)** | The **healthcare** connector uses mock data only. Do not use it with real patient data. Do not put protected health information in workflows without an agreement and review. |
| **Card data (PCI)** | Do not pass card numbers through workflow inputs or tools. |
| **Certifications and data location** | For SOC 2, ISO, regional hosting or subprocessor questions, [contact us](https://agentruntime.io/contact). |
| **AI providers** | AI calls go to the provider you configure (such as OpenAI, Anthropic or Google). Review their data terms. |

## Shared responsibility

| You are responsible for | AgentRuntime is responsible for |
|-------------------------|--------------------------------|
| Keeping API keys and webhook secrets private | Checking permissions on every request |
| Giving connections only the access they need | Separating workspaces from each other |
| What your workflows do and what data they handle | Verifying webhook signatures |
| What you put into AI prompts | Measuring usage and recording admin actions |
