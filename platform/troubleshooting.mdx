This page is for anyone whose workflow did not do what they expected. Find your symptom below, follow the steps, and use the table at the end if you still need help.

## Before you start

Have these ready: the workflow name, the run you are looking at, and the time it happened. You can find runs in [Command Center](/workflows/command-center) and in **Workflow Studio**.

## A run failed

### Find the cause

1. Open **Command Center**. Runs that need attention appear under **Needs you** (approvals) and **Issues today** (the last 24 hours). The **Stopped with errors** list shows failed runs.
2. Click the failed run to open it.
3. Find the step marked **Failed**. Read its error message. This is the step that caused the failure.

**You should see:** one step marked **Failed**, and other steps marked **Completed**, **Cancelled** or **Skipped**.

### What the step labels mean

When one step fails, the whole run fails. The other steps explain what happened around it.

| Label | Meaning | What to do |
|-------|---------|------------|
| **Failed** | This step caused the failure | Fix the cause (model, credential, tool settings or workflow) |
| **Cancelled** | It was running at the same time when the run failed | Nothing. It is part of the record. |
| **Skipped** | It never started because a step before it failed | Nothing. It will run on a new run once the earlier step works. |
| **Completed** | It finished before the failure | Its output is available for you to inspect |

### Common failure reasons

When a step fails, the run fails with that step's error message. Open the run's **Events** tab and read the failed step's error.

| Failed step | What to check |
|-------------|---------------|
| `mcp` (tool) | The tool's inputs, the connection, and whether the outside service is up. A tool call is cut off after 120 seconds. |
| `llm` | Your key under **Providers** and the model name |
| `agent` | The agent's model and tools. If it reached its tool call limit, see [Agents](/ai/agents). |
| `human` | "human_task timed out" means nobody answered in time. See [Human tasks](/workflows/human-tasks). |
| `lua` | The script's own error, or an `error("...")` it raised. See [Lua scripts](/workflows/lua). |

Some failures also carry a code, shown for support and API users:

| Code | What it means | What to do |
|------|---------------|------------|
| `INSUFFICIENT_CREDITS` | The run could not start: the workspace has too few credits | Add credits. See [Billing and credits](/platform/billing-and-credits). |
| `WORKER_LOST` | The worker running a tool, `workflow` or Cursor Cloud step stopped responding, and the step was not run again because it may already have had an effect | Check whether the step acted, then start a new run. See [How runs execute](/workflows/how-runs-execute). |
| `EPISODE_STALLED` | The agents in an [agentic workflow](/workflows/autonomous-episodes) stopped making progress | Give the agents clearer instructions or inputs |
| `EPISODE_TURN_LIMIT` | The agents used all their turns without finishing | See [Limits](/platform/limits) |
| `EPISODE_NO_ENTRY` | No agent step could start the agentic workflow | Grant entry to a step when you start the run, or turn off **Require entry grant** on one step |
| `UPSTREAM_ERROR`, `DEPENDENCY_UNAVAILABLE` | The Console could not reach the workflow service | Try again in a few minutes. Contact support if it keeps happening. |

### Try again after fixing

A failed run cannot be resumed. Fix the cause, publish a new version if you changed the workflow, and start a **new run**. Resuming from the failed step is planned but not available yet. See [Run recovery](/workflows/run-recovery).

## A run seems stuck

| What you see | What it usually means | What to do |
|--------------|-----------------------|------------|
| **Paused** | Someone paused it, or an approval step is waiting | Click **Resume**, or approve the task in **Command Center** |
| Waiting for approval | A `human` step is waiting for a person | This is normal. Approve or reject it. |
| A step stays **Running** | A slow tool or AI call | Check the outside service. Stop the run if needed. |
| **Queued** or **Starting** for a long time | The run has not begun | Check that you have credits and that **Dry-run** shows no errors |

A run that is waiting for a person is working as designed. It is not stuck.

## A tool step fails or "not connected"

<Steps>
  <Step title="Check the connector">
    Go to **MCP**, open the connector, and open **Instance config**. Confirm it is linked to a connection and that the connection is active. The **Validate** page for the connector (`/mcp/<server>/validate`) can also check it.
  </Step>
  <Step title="Check the connection">
    Go to **Connections**. If the connection needs signing in again, click **Reconnect** (for example on a Google account).
  </Step>
  <Step title="Dry-run the workflow">
    In Workflow Studio, click **Dry-run**. Each problem is listed on its step as a **Dry-run error** or **Dry-run warning**. See [Dry-run](/workflows/dry-run).
  </Step>
</Steps>

Connector guides: [Google Workspace](/integrations/google-workspace), [WhatsApp](/connectors/whatsapp), [Gmail](/connectors/gmail), [Postgres](/connectors/postgres).

After you reconnect or change credentials, old failed runs are not fixed. Start a new run.

## You are out of credits

1. Go to **Settings → Usage & History** and look at **Credits remaining**.
2. Look at **Usage history**, and at **Analytics**, to see which workflows use the most.
3. Go to **Settings → Billing Overview** and click **Add credits**, or change plan under **Plans**. You need the workspace **Admin** or **Owner** role.

Credits are used in this order: trial, then included, then pay-as-you-go. See [Billing and credits](/platform/billing-and-credits).

## A connection says Reconnect

This usually means a login expired or was revoked at the service (Google, LinkedIn and others).

1. Open **Connections**, open the account, and click **Reconnect**.
2. Check the connectors that use it in **MCP**.
3. For Google Workspace, ask your Google admin whether third-party apps are allowed.

## API errors

| Error | Likely cause | What to do |
|-------|--------------|------------|
| `401` | Missing, expired or revoked credentials | Send `Authorization: Bearer <key>`. Sign in again, or create a new API key in **Settings → API keys**. |
| `403` | Your project role or the key's scopes are too narrow | You need **Contributor** to change things. Billing changes need a workspace admin. Add scopes such as `workflow:run` or `mcp:execute` to the key. |
| `400 X-Tenant-Id required` | The workspace could not be worked out | Send the `X-Tenant-Id` header, and `X-Project-Id` where needed |

See [API authentication](/api/authentication) and [Roles and permissions](/platform/roles-permissions).

## Template values look wrong

If a field shows a literal `{{ ... }}` in a run, or a variable is missing, clear the field and pick the variable again from the suggestions. Click **Dry-run** to check step references. See [Template intellisense](/workflows/template-intellisense).

## Still stuck?

Email [support@agentruntime.io](mailto:support@agentruntime.io) with:

- the workflow name and run
- the error message or failure reason
- the step that failed
- the time it happened
