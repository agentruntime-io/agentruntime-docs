This page is for anyone new to AgentRuntime. It explains the main ideas in the order you will meet them. Read it once, then use it as a glossary.

## Workspaces

A **workspace** is your organization's space in AgentRuntime. It holds your projects, members, billing, tool connections and settings. Each workspace is separate from every other workspace.

A workspace has a **name** and a **handle** (a short identifier used in links and API calls). Change them in **Settings → General**.

## Projects

A **project** groups related work inside a workspace, such as "Marketing automations" or "Support bot". You switch projects from the project switcher in the Console. You set a **default project** from the **⋮** menu next to a project in that switcher (**Set as default project**).

Projects can be **public** (every workspace member can use them) or **private** (only members you add can use them). Change this under **Project settings → Project visibility**. See [Roles and permissions](/platform/roles-permissions).

| Resource | Where it lives |
|----------|----------------|
| **Workflows** | Always in one project |
| **Runs and approval tasks** | In the project of their workflow |
| **Agents, connections, MCP instances** | Shared across the workspace by default. You can choose project scope when you create them. |

<Info>
  A member can have a different role in each project. For example, someone can be a **project viewer** in one project and a **contributor** in another.
</Info>

## Members and roles

Access has two layers:

- **Workspace role** (**Member**, **Admin**, **Owner**) controls team, billing and workspace policy.
- **Project role** (**Project viewer**, **Contributor**, **Project admin**) controls what you can do inside a project.

The role names used in the API are `project_viewer`, `project_contributor`, `project_admin` and `tenant_admin` (the workspace admin). The [Roles and permissions](/platform/roles-permissions) page has the full table.

## Workflows

A **workflow** is a set of **steps** that run in order, where each step can use the results of earlier steps. You build workflows in **Workflow Studio**, check them with a **Dry-run**, publish a version, and then start **runs**.

Common step types:

- `mcp` — use a tool, such as sending an email
- `llm` — ask an AI model
- `human` — pause until a person approves or provides input
- `lua` — transform data with a small script
- `for_each` — repeat steps for every item in a list
- `while` — repeat steps while a condition holds

Steps use earlier results with template variables like `{{steps.fetch-contacts.result.items}}`. Values supplied when a run starts look like `{{input.topic}}`. See [Step types](/workflows/step-types) and [Run setup](/workflows/run-setup).

## Runs

A **run** is one execution of a published workflow version. The Console shows each step starting and finishing live. You can **pause**, **resume** or **stop** a run from Workflow Studio, Command Center or the API.

**Command Center** is your inbox for runs that need attention, such as approvals waiting for you and runs with issues.

## MCP servers and instances

**MCP** (Model Context Protocol) is the standard AgentRuntime uses to talk to tools. An **MCP server** is a catalog entry for a tool, such as Gmail. An **MCP instance** is that server set up in your workspace, linked to your credentials. Workflow `mcp` steps use instances.

## Connections

A **connection** is a saved login or API key for a tool: a Google account, WhatsApp credentials, or a plain API key. You save connections in **Connections** and link them to MCP instances. That way workflows never contain your secrets.

## Agents and Autopilot

**Agents** are reusable AI assistants you set up in your workspace. They can hold multi-turn conversations and use tools. **Autopilot** is the assistant built into the Console. It can answer questions, create workflows and start runs. See [Autopilot and chat](/ai/autopilot-and-chat).

## API access

You can work with AgentRuntime from code in three ways:

- **Console sign-in** — the browser session you use every day
- **Personal access tokens (PATs)** — keys you create in **Settings → API keys**, limited by scopes such as `workflow:read`, `workflow:run` and `mcp:execute`
- **Platform MCP** — lets tools like your IDE manage workflows through MCP at `mcp.agentruntime.io`

See [API authentication](/api/authentication).

## Billing and credits

Usage is measured in **credits**. Credits are used when workflows run. **Analytics** and **Settings → Usage & History** show what you have used, and **Settings → Billing Overview** and **Plans** manage your subscription. See [Billing and credits](/platform/billing-and-credits).
