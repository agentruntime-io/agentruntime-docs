title: Runs
description: Find runs across your workspace, stop paused runs, and see and manage the triggers that start workflows, from one page.

The **Runs** page is the Console page for the day-to-day running of your workflows. It has two tabs: **Runs** and **Triggers**. Above the tabs, a strip of three chips shows the health of your workspace at a glance.

Open it from **Runs** in the **Run** group of the Console sidebar (at `https://console.agentruntime.io/operate`).

**Who this is for:** people who keep workflows running in production. To add, change, or delete a trigger on the **Triggers** tab you need the `project_contributor` role (or higher). With a lower role you can read the list, and the tab says "Contributors can add and change triggers."

**What you will do on this page:** find a run, deal with runs that stay paused, and add and check triggers.

## Runs, Command Center or Studio?

Three places show runs. Pick the one that fits your question.

| Place | Use it to | Scope |
|---|---|---|
| **Runs** page | Find any run with filters (status, workflow, agent, started by, trigger, dates, run ID). Stop old paused runs. See and manage triggers. | The whole workspace, or one project |
| [Command Center](/workflows/command-center) | Answer approvals and replies, follow up missed tasks, and pause or stop runs that are in progress | The whole workspace |
| [Workflow Studio](/workflows/studio) run panel | Read one run step by step in **Events**, **Timeline**, **Context** and **Full Logs** | One workflow |

A run row on the **Runs** page links to the other two: **Approve** opens the task in Command Center, and the workflow name and **Debug** open the run in Studio.

## What you see at the top

The page title area shows a **Times** button. It reads **Times: Local** or **Times: UTC**. Click it to switch how the **Runs** tab shows times. Your choice is remembered in this browser.

Under it, a hint tells you which projects you are looking at:

- When a project is selected, it says "Showing runs and automation for project" and the project name.
- When no project is selected, it says "Viewing all projects in this workspace" and offers **Filter to** your sidebar project.

The **Runs** page opens on the project you picked in the sidebar. To see the whole workspace, choose **All projects** in the **Project** filter. The page remembers that choice until you close the browser tab.

### The health strip

Three chips sit above the tabs. Click a chip to jump to the matching list.

| Chip | What it counts | Where it takes you |
|---|---|---|
| **Unfinished runs** | Runs that are running, pending, queued, starting, draining or paused | **Runs** tab, with the **Status** filter on **Unfinished** |
| **Failed trigger fires (24h)** | Events that a trigger accepted but that did not start a run in the last 24 hours (failed, blocked, or given up on), across all your triggers. The chip turns to a warning style when the number is above 0. | **Triggers** tab |
| **Triggers needing attention** | Triggers that are paused because the person they run as lost access, or whose app registration needs attention. The chip turns to a warning style when the number is above 0. | **Triggers** tab |

A count that ends in a plus sign, such as **100+**, means "at least this many". The chip then reads **Unfinished runs (in view)**.

## Find a run

<Steps>
  <Step title="Open the Runs tab">
    Click **Runs** in the sidebar. The **Runs** tab is the first tab.
  </Step>
  <Step title="Set the filters">
    Use the **Filter runs** section. See the table below. Each change updates the list. Every filter except **Run ID** is also saved in the address of the page.
  </Step>
  <Step title="Read the list">
    Each row is one run. A line under the filters says how many runs are loaded. When there are more, click **Load more** at the bottom. Each page holds 50 runs.
  </Step>
</Steps>

### Filters

| Filter | Choices | Notes |
|---|---|---|
| **Project** | **All projects**, or one project | A project shows the runs of the workflows that belong to it. Changing the project clears the **Workflow** filter. |
| **Status** | **All statuses**, **In progress**, **Paused**, **Unfinished**, **Completed**, **Failed / stopped** | **In progress** means running, pending, queued, starting or draining. **Unfinished** adds paused runs. **Failed / stopped** also includes cancelled runs. |
| **Workflow** | **All workflows**, **Agent sessions (workspace-copilot-session)**, or one workflow | When no project is selected, each workflow shows its project name after it. |
| **Agent** | **All agents**, or one agent | |
| **Started by** | **Anything**, **Schedule**, **App event**, **HTTP call**, **Workspace event**, **Phone call**, **API**, **Chat**, **Manual** | How the run started. Choosing one clears the **Workflow** filter. **Started by** is locked to chat while **Workflow** is on **Agent sessions**. |
| **Trigger** | **Any trigger**, or one trigger | Only the runs that trigger started |
| **From**, **To** | A date each | Limits the runs to a date range. |
| **Run ID** | Part or all of a run ID | From 4 characters, the page asks the server to find the run. With fewer characters it only filters the runs already loaded. |

Two buttons sit next to the filters:

- **Paused > 7 days** shows only runs that have been paused for 7 days or more. See [Stop old paused runs](#stop-old-paused-runs).
- **Copy link** copies the address of this view. See [Share a filtered view](#share-a-filtered-view).

On a narrow screen, the filters move into a **Filter runs** button that opens a sheet from the bottom.

### Read a run row

| Part | What it shows |
|---|---|
| Workflow name | Click it to open the run, the same as **Debug** |
| Status badge | The run's status. **Stalled** replaces the badge for a run that looks active but has shown no progress for 2 hours or more. Hover for how long it has been quiet. |
| **Needs approval** | A person has to answer a task in this run |
| Details line | The project, the agent, how long the run took (a paused run shows **Paused**, since when, and how long it has been open), the start time, how it started (for example **Started by Schedule · Weekday report**), and a short run ID |

Runs that come from an agent or a chat conversation (agent sessions) use plain wording for the status: **Reply in progress**, **Turn complete** or **Waiting for reply**.

The buttons on the right of a row depend on the run:

| Button | What it does |
|---|---|
| **Pause**, **Resume** | Pause a running run, or continue a paused one |
| **Stop** | Ends the run. The main button is a **Force stop**. The arrow beside it offers **Force stop**, **Stop immediately** and **Stop gracefully**. See [Control a run](/workflows/runs-and-command-center#control-a-run). |
| **Approve** | Opens the waiting task in Command Center |
| **Chat** | Opens the run's chat conversation in a new browser tab. Shown only for runs that belong to a conversation. |
| **Debug** | Opens the run in Workflow Studio on the **Events** tab. For an agent run it opens the agent's run page instead. |

### Stop old paused runs

A run can stay paused for days, for example when nobody answered a task. Use these controls to clean them up.

<Steps>
  <Step title="Click Paused > 7 days">
    The **Status** filter changes to **Paused** and the list shows only runs that have been paused for 7 days or more. The page counts from the run's last progress, or from its start if it has none.
  </Step>
  <Step title="Load the runs you want to stop">
    If the list says there are more runs, click **Load more** until the runs you want are on screen.
  </Step>
  <Step title="Click Stop all in view">
    A bar above the list reads "N paused runs older than 7 days in this view." Click **Stop all in view** on that bar. Each of those runs gets a **Force stop**. A message tells you how many stop requests were sent.
  </Step>
</Steps>

<Warning>
  **Stop all in view** does not ask for confirmation. It force-stops every paused run older than 7 days that is in the list, and a stopped run cannot be resumed. It does not reach runs that are not loaded, so check the list first.
</Warning>

The bar appears whenever such runs are in the list, even if you did not click **Paused > 7 days**.

Click **Paused > 7 days** again to turn the filter off.

### Share a filtered view

Click **Copy link**. You see the message "Link copied". Send the link to a teammate. When they open it, the **Runs** page shows the same tab and filters.

The link keeps the project, status, workflow, agent, **Started by**, **Trigger**, dates, and the **Paused > 7 days** setting. It does not keep the text in **Run ID**. The person who opens it needs access to the workspace and project. To build links by hand, see [Keyboard shortcuts and links](/platform/shortcuts-and-links#runs-links).

## Triggers

The **Triggers** tab lists the triggers of the project you selected (or of all projects). A trigger starts a workflow run without anyone clicking **Run**: it can be a schedule, an event in an app you connected, a signed call from another system, a workspace event, or a phone call. For what each kind does, see [External triggers](/workflows/external-triggers). For who each run is for, see [Triggers and run identity](/workflows/trigger-run-identity).

### Read the list

Each row shows the trigger's name (or its source, when it has no name), a status badge, where its events come from, the workflow, who it runs as (**Runs as**), when it last fired (**Last fired**), and for a schedule the next run (**Next**). The badge is **Active**, **Paused**, **Needs an owner** or **Needs attention**. A problem, such as an app that refused the registration, shows beside the badge.

| Control | What it does |
|---|---|
| Switch | Pauses the trigger, or resumes it |
| **Details** | Opens the trigger's panel (see [Open a trigger](#open-a-trigger)) |

Use the filters above the list: **Project**, **Kind** (**All kinds**, **Schedule**, **App event**, **HTTP call**, **Workspace event**, **Phone call**) and **State** (**Any state**, **Active**, **Paused**, **Needs an owner**, **Needs attention**). When some triggers need attention, a warning above the list says how many, with a **Show them** button.

### Add a trigger

<Steps>
  <Step title="Click New trigger">
    The **New trigger** dialog opens with the text "Pick the workflow, then what should start it."
  </Step>
  <Step title="Choose the workflow">
    Pick a workflow under **Workflow**. With **All projects** selected, each workflow shows its project name after it.
  </Step>
  <Step title="Choose what starts it">
    Under **What should start this workflow?**, pick a kind, fill in the form, and click **Create trigger**. It is the same form as **Setup → Triggers** in Workflow Studio, described in [External triggers](/workflows/external-triggers#add-a-trigger).
  </Step>
</Steps>

You see the message "Trigger created" and the trigger appears in the list. For an HTTP call, a dialog opens first with the **URL to call** and the **Signing secret**. Copy the secret then. It cannot be shown again.

### Open a trigger

Click **Details** on a row (or use a link with `?trigger=<id>`). The panel shows the workflow, what the trigger **Starts when**, any filters (**Only when**), which version it **Runs**, who it **Runs as**, **Last fired**, and **Last 24 hours**. A schedule also shows **Next run**. Under these is the **Activity** list: each event the trigger received, its status, and an **Open run** button when a run started.

| Control | What it does |
|---|---|
| **Test** | Sends a sample event. The Console asks you to confirm first, because this **starts a real run**. |
| **Pause** / **Resume** | Stops or restarts the trigger |
| **Edit** | Opens the form you used to create it |
| **New signing secret** | HTTP calls only. Makes a new secret and shows it once. Senders that use the old secret stop working. |
| **Renew route** | App events only. Makes a new address and registers it again at the app. It affects every trigger on the same connection. |
| **Delete** | Removes the trigger. Anything registered at an app is removed when this was the last trigger on that connection. |
| **Replay** (in **Activity**) | Runs the same event again. It works for 7 days after the event arrived. |

When a trigger says **Needs an owner**, a banner at the top of the panel says "This trigger paused because (the person) can no longer run it." Workspace admins get a **Run it as me** button. Others see "Ask a workspace admin to run it as themselves."

### Check failed fires

An event that a trigger accepted but could not turn into a run is a failed fire. The cause can be that the person it runs as lost access, or that the workspace is out of credits. To find them, click the **Failed trigger fires (24h)** chip to open the **Triggers** tab, then click **Details** on a trigger and read **Activity**. The row for each event says why. The **Last 24 hours** line shows how many started, failed, were blocked, or gave up.

## Common problems

| Problem | What to try |
|---|---|
| The **Runs** tab says "No runs in" a project, but you expect some | Runs from workflows in other projects are hidden while a project is selected. Click **Show all projects**. |
| **Stop all in view** is not on the page | It shows only when paused runs older than 7 days are in the list. Click **Paused > 7 days**, then **Load more** if needed. |
| A **Run ID** search finds nothing | Type at least 4 characters so the page asks the server. With fewer, it only checks the runs already loaded. |
| You cannot add or change a trigger | You need the `project_contributor` role or higher. See [Roles and permissions](/platform/roles-permissions). |
| A schedule did not start a run | Click **Details** on its row and read **Activity**. Check that the trigger is not **Paused** or **Needs an owner**, and that the person it runs as still has access. |
